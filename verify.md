# Verifying PatientWords

This is the canonical verification guide for the static `patientwords` gallery.
Read the applicable sections when planning a change and again before completion.
[AGENTS.md](AGENTS.md) and [agent_reference.md](docs/agent_reference.md) preserve
ownership, compatibility, research and UI decisions. The checked-in workflow
[site_checks.yml](.github/workflows/site_checks.yml) is the source of truth for CI.
Run the Bash blocks below from this site root. Each uses a subshell with
`set -euo pipefail`, so a failed prerequisite stops the block and its exit status
remains a failure. Directory changes stay inside the block. If a check fails,
report it before running independent follow-up diagnostics separately.

## Setup and scope

There is no build, package manifest, dependency lockfile or Node runtime in this
repository. Preview and JSON checks use Python's standard library; site CI uses
Python 3.11. No application environment variables, credentials, live model calls,
database or backend service are needed to serve the committed site.

The full contract and browser checkers live in sibling `../patientwords-engine`.
Use its [verify.md](../patientwords-engine/verify.md) for engine dependency setup
and producer tests. A full engine checkout is preferable: contract checks read
its `../patientwords-engine/scripts/`, `../patientwords-engine/data/`,
`../patientwords-engine/ops/` and `../patientwords-engine/docs/`. These include
publication disclosures and vendor-pack state. Claim/seal checks additionally need their committed sources.
A sparse site checkout hiding tracked files is not sufficient for export/seal
checks; restore those paths before claiming a complete sweep.

For browser checks, activate the engine's verification environment, then install
Playwright and Chromium there (the same additional installation site CI makes):

```bash
(
set -euo pipefail
cd ../patientwords-engine
# Engine verification environment active
python -m pip install playwright
python -m playwright install chromium
# Linux CI also installs system dependencies:
# python -m playwright install --with-deps chromium
)
```

This installation requires network access; running against committed local files
then needs no live research service. Playwright is not locked by this site's CI;
record the installed version when browser/environment differences matter. The
separate synthetic boundary suite uses its own locked tools below. If a
Chromium executable is already available, pass its actual path with the checker's
`--browser` argument; do not assume a machine-specific `/opt/` path exists.

`PW_SITE_ROOT` is optional for engine tests that compare shared instructions or
claims against a non-sibling checkout. Pass an absolute site path if set; the CLI
checkers instead use their explicit `--site` flags. No application `.env` is used.

## Quick path: independent of the engine

Run from this repository root:

```bash
(
set -euo pipefail
git status --short --branch
git rev-parse HEAD
python3 - <<'PY'
import json
from pathlib import Path
paths = sorted(Path('data').rglob('*.json'))
assert paths, 'no JSON payloads found under data/'
for path in paths:
    json.loads(path.read_text(encoding='utf-8'))
print(f'{len(paths)} JSON files parse')
PY
git diff --check
)
```

Success proves that committed/local JSON is syntactically readable and the diff
has no whitespace errors. It does **not** validate payload schemas, source
measurements or rendered behavior. For documentation-only changes, also inspect
all changed links/anchors and commands against actual files and CLI definitions;
review new untracked guidance as well as `git diff`. There is no standalone site
Markdown/link checker. No files are generated by this quick path.

## Select checks by change

| Change | Applicable checks | What to inspect beyond a pass |
|---|---|---|
| Repository guidance/verification docs | Quick path; execute changed commands; paired documentation tests; shared-instruction tests if `AGENTS.md` or `CLAUDE.md` changes | Nested/override consistency, local links and counterpart revisions |
| Static research prose, captions or provenance | Quick path, claim and seal gates; contract/pages if data references or HTML change | Source-backed quantities, population/uncertainty, simulated/sample/draft labels and acknowledgments |
| HTML/CSS/JS behavior | Quick path, both site CI gates and affected manual interactions; synthetic boundary suite when scenario-index behavior changes | Keyboard/focus, mobile layout, model/filter/sort states, pending values |
| Exported JSON, render paths or schema | Fix/regenerate in engine; its focused producer tests and synthetic boundary suite; contract, claims, seal, pages and affected manual interactions | Base mirror, model metadata, stable provenance keys, holdout/publication restrictions and both revisions |
| Engine logic affecting this site | Engine focused and required broader checks, then regenerate/validate affected artifacts and exercise consumers | A passing fixture test is not a real generation-to-render run |
| CI, hosting, paths or domain configuration | Both site CI gates, engine tests for changed checker behavior, manual project-path/deep-link/404 checks | Workflow engine-ref resolution, sparse paths, canonicals and deployment settings outside the checkout |

Site CI runs both contract and browser gates for every push/PR, including docs
changes. Proportional local selection does not remove those required CI gates.
Research publication retains the existing claim and seal checks even though the
site's own CI workflow only runs the first two gates below.

## Paired contract and browser gates

Use sibling checkouts unless explicit flags point elsewhere. Record both HEADs
and relevant dirty files before starting; an uncommitted counterpart is part of
the tested state, not equivalent to its HEAD alone.

```bash
(
set -euo pipefail
# Working directory: patientwords (this repository)
git rev-parse HEAD
git -C ../patientwords-engine rev-parse HEAD
git -C ../patientwords-engine status --short --branch

cd ../patientwords-engine
# Engine verification environment active
python scripts/validate_frontend_contract.py --site ../patientwords --engine .
python scripts/check_pages.py --site ../patientwords --json /tmp/patientwords-page-report.json
)
```

Run contract first. Its simulated payload structure comes from engine
`../patientwords-engine/scripts/contracts/simulated_scenarios.v1.schema.json`.
Its limited standard-library adapter retains stricter integer-token handling than
general draft-07 validation. Semantic checks cover relationships beyond schema
shape. It rejects missing/renamed/wrong-type fields, duplicate joins,
noncontiguous scenario display indices, inconsistent base-model mirrors, missing
render paths, invalid sample/real relationships and incompatible engine copies.
It also checks publication/vendor-pack state. Read its warning output: normal
site CI deliberately does not pass `--strict`; that mode turns warnings into
errors. The engine's publication chain requires `--strict` once urgency regeneration
has written `unjoinable_rows`; preserve that stronger gate when publishing. Report
the normal CI gate's warnings too; do not weaken checks to hide them.
`--engine ''` only skips some copy comparisons: the CLI still reads checker-side
publication/disclosure data and is not a self-contained site-only validation.

`check_pages.py` discovers composed HTML pages, excluding `modes/`, launches a
local server on `127.0.0.1:8901`, drives Chromium, and terminates its server in a
`finally` block. Success means no detected page/console errors, failed data/HTTP
requests or empty **visible** known JS tables. Hidden empty and populated collapsed
tables have deliberately different handling. It does not exhaustively validate
page values, generated figure contents, interactive controls or deep-link variants.
Use `--port 8902` if 8901 is occupied; ensure the chosen port is free before running.

The workflow pairs site `main` with engine `main`; other branches use the exact
same **remote** engine branch if it exists, otherwise engine `main`. A matching
local branch alone does not establish the hosted pairing. The workflow keeps
`scripts`, `data`, `ops` and `docs` in its sparse engine checkout; the schema stays
under `scripts`. Synthetic boundary tests additionally need `tests` and are not
part of active site CI. The inactive proposal in `docs/boundary-check.yml.example`
requires an explicit immutable engine SHA if later authorized. A local run proves
the recorded local pairing only. No fetch, branch switch or publication is required
for verification; do not silently replace a dirty checkout to match CI.

## Claims, holdouts and shared instructions

Start from the site root with the engine verification environment active:

```bash
(
set -euo pipefail
cd ../patientwords-engine
python scripts/claim_check.py --site ../patientwords
python scripts/seal_check.py --site ../patientwords
python -m pytest -q tests/test_shared_conventions.py tests/test_claim_check.py tests/test_doc_paths.py
)
```

The claim checker recomputes entries in
`../patientwords-engine/data/claims_manifest.json` from site data and checks their prose snippets. A missing snippet is a **warning that
can exit 0**; inspect it. The live-manifest pytest test requires both failures and
warnings to be absent. Neither checks claims not registered in the manifest.

The seal checker uses `../patientwords-engine/data/simulated/`,
`../patientwords-engine/ops/dashboard.json` and
`../patientwords-engine/data/seal_allowlist.json`. It scans the site plus
`../patientwords-engine/docs/`, `../patientwords-engine/ops/` and
`../patientwords-engine/data/verification/` by default. Success is a clean sweep
of the files actually available. Exit 1 is a leak; exit 2 is a configuration/incomplete-checkout problem.
Never paste sealed phrase text into a report; report the checker IDs and paths.

Shared-convention tests compare the generic `## Code Review Rules` block of both
`AGENTS.md` files and the shared-conventions block in both `CLAUDE.md` files byte
for byte. With no default sibling, cross-repository tests visibly skip; a skip is
not a paired pass. The engine's `../patientwords-engine/tests/test_doc_paths.py`
also checks named paths in the paired operating guides; it does not replace
reviewing prose accuracy or running the documented commands. To pass this sibling
site explicitly:

```bash
(
set -euo pipefail
PW_SITE_ROOT=$(pwd)
export PW_SITE_ROOT
cd ../patientwords-engine
python -m pytest -q tests/test_shared_conventions.py tests/test_claim_check.py tests/test_doc_paths.py
)
```

When changing the engine's validator or browser checker, its focused tests include
`../patientwords-engine/tests/test_validate_frontend_contract.py`,
`../patientwords-engine/tests/test_simulated_schema.py`,
`../patientwords-engine/tests/test_check_pages.py` and
`../patientwords-engine/tests/test_check_pages_browser.py`. Browser regression
tests may skip without
Playwright/Chromium; report their actual counts. These are checker/fixture tests,
not proof that today's exported site renders correctly.

## Synthetic exporter-to-browser check

Run this when changing the simulated schema/export path, generated response models,
test client, or scenario-index behavior. The current bounded path lives in engine
[frontend_boundary.md](../patientwords-engine/docs/exploratory/frontend_boundary.md).
The fixture is `../patientwords-engine/tests/fixtures/frontend_boundary.json`.
It deliberately uses synthetic inputs and expected values, not research observations.

Prerequisites are Python 3.13, a separate environment installed from engine
`../patientwords-engine/scripts/boundary_client/requirements.lock`, and Chromium.
Setup downloads packages and a browser; the check itself uses only local files and loopback HTTP. Run from
this site root. Choose a different `PW_BOUNDARY_ENV` directory if the path is
already used for another purpose.

```bash
(
set -euo pipefail
cd ../patientwords-engine
PW_BOUNDARY_ENV=/tmp/pw-boundary-venv
python3.13 -m venv "$PW_BOUNDARY_ENV"
"$PW_BOUNDARY_ENV/bin/python" -m pip install -r scripts/boundary_client/requirements.lock
"$PW_BOUNDARY_ENV/bin/python" -m playwright install chromium
"$PW_BOUNDARY_ENV/bin/python" scripts/check_frontend_boundary.py \
  --site ../patientwords --receipt /tmp/patientwords-boundary-receipt.json
)
```

With that environment and browser already installed, the repeat command is:

```bash
(
set -euo pipefail
cd ../patientwords-engine
/tmp/pw-boundary-venv/bin/python scripts/check_frontend_boundary.py \
  --site ../patientwords --receipt /tmp/patientwords-boundary-receipt.json
)
```

Use `--browser /actual/path/to/chromium` only when selecting an existing executable.
The runner creates temporary sibling checkouts, runs selected offline tests in
that sparse layout, invokes the real exporter on synthetic inputs, validates the
output and generated-model regeneration, and serves the real index under
`/patientwords/`. It asserts displayed probabilities, sign/axis conventions,
row/model identity, search/outcome filtering, zero/missing values, untraced-model
states and legacy fallback. Deliberate malformed-response and swapped-model
controls must fail, then pass after restoration. The client validates raw HTTP
responses against the authoritative schema before using generated models.

Success produces a fresh receipt binding engine/site HEADs, dirty-file identities,
fixture/schema/toolchain hashes, versions and checkpoint results. Inspect its
`result` and checks, not the historical receipt committed with the earlier work.
The runner cleans its temporary exports and server on exit; it writes nothing to
published `data/` or `modes/`. This is exercised synthetic generation through the
real HTTP and browser path. It is not a real-model run, deployed-site check,
full-site contract/publication gate, detail-page regression or clinical result.
The index has no native sample mode; the temporary page visibly discloses the fixture.
The detail-page `pct(0)` negative-zero/absolute-gap wording issue recorded in the
engine boundary document remains outside this suite and needs a separate regression.

## Producer-to-consumer boundary

This gallery consumes exported artifacts, not a live API. The engine's
`../patientwords-engine/scripts/export_frontend_simulated.py` reads generated
batches and report sidecars under `../patientwords-engine/data/simulated/`, plus
model-specific `../patientwords-engine/trace_out/` summary parts and renders.
It writes site `data/simulated_scenarios.json` and a capped selection under
`modes/simulated/`. See the engine [verification guide](../patientwords-engine/verify.md)
for producer setup, focused export tests and safe regeneration. Preserve selected
stamp order, steered-stamp disclosure, source/model metadata, seeds and existing
publication decisions. A dry run writes/deletes nothing; a real export can prune
unreferenced renders and needs complete source/site trees. Do not regenerate a
published dataset merely to test a documentation change.

There is no separate `scenario_index.json` artifact or scenario-index build in
these checkouts. `simulated-scenarios/index.html` fetches the payload directly;
`scenario.html?sim=N` finds contiguous `scenario.index` and uses adjacent indices
for navigation. That number is display order and can change on re-export. Stable
research identity is `(batch, batch_index)`; per-model urgency joins add `model`.
The list page also loads urgency, provenance, depth and specialty payloads.

After raw export, the engine must restore urgency/depth enrichment with
`../patientwords-engine/scripts/embed_scenario_joins.py` and trace URLs with
`../patientwords-engine/scripts/export_traces_site.py --stamp-only`, after any affected collectors.
The contract permits these optional fields to be absent: a passing schema check
does not prove that enrichment ran. Inspect join counts and the rendered fields.

The supported check sequence is producer output and postprocessing → contract
validator → served list/detail loading → affected model/filter/sort/render behavior.
Preserve the base-model mirror and `models_meta` feature/graph capabilities. Old payload
fallbacks and unmeasured models must show pending/em-dash states, not borrowed
numbers. Owner-run Multi-turn real files are paired; `?sample=1` uses labeled
synthetic fixtures. Samples under `data/*.sample.json` support development but do
not validate a live generation or research finding.

A frontend-only quick check verifies syntax and a browser can inspect committed
artifacts. Engine fixture tests verify producer/validator behavior independently.
The synthetic boundary runner exercises fresh fixture export, HTTP loading and
index rendering together; it does not use live generation or published observations.
The actual export-to-render path requires both repositories and the needed source
artifacts. Report the engine/site revisions, source stamps or artifact hashes,
and whether generation was actually run. Loading an existing payload is a paired
compatibility check, not exercised fresh generation end to end.

## Manual checks and cleanup

From the site root, run `python3 -m http.server 8900 --bind 127.0.0.1` and inspect
the affected page at `http://127.0.0.1:8900/`. For scenario behavior:

- Compare displayed counts and a sampled row/detail to the payload, taking active
  filters/pagination into account. Check search, specialty/filter chips, sorting
  in both directions, model switching, and `aria-pressed`/`aria-sort` states.
- Open a known `?sim=N&model=...` detail, previous/next navigation and an invalid
  scenario ID. Check an unmeasured model and graphless/features-disabled model.
  Follow a published render and inspect its labels; the page smoke gate excludes
  `modes/`. Exercise legacy/missing optional fields with temporary local fixtures
  or request interception, never by mutating published source data.
- For advice/Multi-turn changes, inspect both default real data and `?sample=1`,
  coherent paired fallback, visible sample notices, provenance and draft labels.
- Check keyboard focus, screen-reader labels and a narrow viewport. For URL or
  hosting changes, serve the site's parent directory and open `/patientwords/`
  to exercise the project prefix; inspect `404.html` links and canonical URLs.
  Python's server does not reproduce GitHub Pages' custom-404 routing, so a
  production/staging hosting check is still needed for that behavior.

Stop a manual server with Ctrl-C. The automated page checker owns and terminates
its own server; if interrupted externally, stop only the process you started.
Remove or retain `/tmp/patientwords-page-report.json` and
`/tmp/patientwords-boundary-receipt.json` deliberately; they are session artifacts,
not repository guidance. Remove the isolated `/tmp/pw-boundary-venv` only when it
was created for this work and is no longer needed; do not delete shared browser
caches. Temporary fixture/staging copies belong outside
the checkout and should be removed when no longer needed. Do not remove unrelated
untracked files or cache directories as cleanup.
