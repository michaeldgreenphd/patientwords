    Run status

    Every method the protocol planned, including those that did not run. A planned task with no recorded state reads state not recorded; it is never read as completed.

    completed
    The task finished and its result is recorded. A zero or an opposite-direction result is also completed.
    unsupported
    The capability matrix says this combination of method and model cannot run.
    unavailable
    The combination could run in principle; a required input is absent or its identity is unknown.
    not_run
    The task was planned and no result is recorded for it.
    failed
    An attempt ended in an error. The recorded reason is in the table.
    invalid
    An attempt was refused, or its result did not pass validation. The recorded reason is in the table.

    About this comparison

    Evidence labels, protocol, model and tokenizer as recorded

    What the primary output is

    Target-token probability is the model's next-token probability of the first encoded token of the target, over the full vocabulary. A target that encodes to several tokens is scored on its first token only, so the value is not the probability of the whole word. A difference between two wordings is given in probability, as the first wording minus the second; 0.01 is one percentage point.

    How to read the ranks and the internal measurements
    Vocabulary rank
    The rank printed beside a target-token probability is the rank of that token among all vocabulary tokens at the output.
    Readout rank
    The rank of the target token when one internal layer state is read out. It is an instrument's readout, not the model's output. Raw rank counts every vocabulary token; filtered rank counts only the tokens the filter keeps.
    ICA component
    A signed component score is the coordinate of the layer state along one component of a fixed basis; it can be negative. A squared-coordinate share is that coordinate squared, divided by the sum over all components; it is not a probability. A name given to a component is a hypothesis.
    Units
    Each block keeps its own unit. Nothing on this page adds or averages a probability, a rank, a component score and a review label, and only probabilities are drawn on the 0 to 1 axis.
    Wording names
    The file names its variants clinical, colloquial and a third required variant. This page shows them as Medical wording, Everyday wording and Rewritten wording. The file's own names are in the protocol record above.

    Labels on this page and the schema terms they stand for

    Compare methods
    A method-comparison bundle: one file of schema patientwords.experiment-bundle/1, written by the engine's experiment interface.
    Cases
    Case families: protocol.families and comparisons[].family_id. One family is one case in several wordings (variants).
    Run status
    Execution state: execution.by_state and methods_not_run[].states.
    Analysis eligibility
    Analysis membership: evidence.analysis_memberships, the analysis rules the protocol declares. A declared rule states eligibility, not use in a statistic.
    Study version
    The analysis pin: protocol.id, protocol.version and protocol.sha256, the hash every task of the run is bound to.

    Provenance: provenance, plan_totals and execution.
