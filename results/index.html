About this catalogue

This is the full list of measured runs. It is not a sample and it is not a claim. A run is listed whether its effect is negative, zero or positive, whether it finished or stopped part-way, and whether or not any analysis includes it.

What is measured. Target-token probability: the next-token probability of the first encoded target token, on a scale from 0 to 1. It is a lexical proxy for language-model behaviour. It does not measure whether an answer is correct, how risky a reply is or what a patient understands. Each row is one measurement; the files carry no interval and no effect estimate. Nothing here is medical advice.

The stimuli. The phrasings are test stimuli written by a model or by hand. They are not statements from patients. Clinical review status of the stimuli: not loaded.

Evidence class. It differs between runs and is stated on each row: not loaded. Whether an analysis includes a run is a separate fact, decided by a named rule in Methods & source.

How the files join, and what the fields mean

Joining the files

The CSV files join on stem and index, except rows marked own_prompts: those were traced with other text, which rows.csv carries in own_clinical_prompt and own_patient_prompt. Sealed rows are in neither file.

Row fields

run_dir · stem · index · part
the run id (the engine's run directory name), the stimulus set, the pair's index in that set, and the batch summary part that holds the row
prob_clinical · prob_patient
target-token probability after the clinical wording and after the patient wording
language_penalty
prob_patient − prob_clinical, shown on this page as Difference. Negative: the target token is less likely after the patient wording. Zero and positive values are results and are listed the same way.
target_token · top_clinical · top_patient · flipped
the token whose probability is measured; the most likely next token after each wording; whether those two top tokens differ
screening_status
the screening record of the row, when the run recorded one
part_state · analysis_memberships
the Run status of the row's part (execution_state) and the analyses that include the part (Included in analysis)

A membership is a named rule that decides which parts may enter an analysis. Being listed in this catalogue does not place a run in any analysis. Each run's Methods & source gives the reason for every part outside a rule.

Restriction Count Scope Responsible role Release condition

Each count states its unit: rows for a row-scope restriction, parts for the others. For clinical-feature mass it is the number of listed parts whose rows omit that field. A restriction names who can lift it and under what condition. Nothing else is withheld from this catalogue.
